# Everything_Mew v0.4.0 Release Notes / 릴리스 노트

Status: stable release prepared on 2026-10-08. The Python package version is
`0.4.0` and the Git tag is `v0.4.0`.

상태: 2026-10-08에 준비한 안정판입니다. Python 패키지 버전은 `0.4.0`, Git
태그는 `v0.4.0`입니다.

## English

### Summary

Version 0.4 makes the Everything index the fast path for file discovery in
Windows agent work. Agents usually find files by walking directories, and a
walk gets slower as the tree grows. An Everything query does not walk the
tree, so it stays near 0.1 s.

| Search on a 603k-file user profile | Claude Code Glob | PowerShell walk | Everything_Mew |
| --- | ---: | ---: | ---: |
| `*.toml` | 9.0 s | 25.7 s | 0.15 s |
| `pyproject.toml` | 10.2 s | 25.8 s | 0.11 s |
| `.py` changed today | not supported | 29.3 s | 0.18 s |

End to end with `claude -p` (Sonnet, two runs each), the "`.py` changed today"
task took 16.5 s with Everything_Mew and 216.7 s with built-in tools only. The
"find every `pyproject.toml`" task took 18.8 s instead of 27.2 s, and both
Everything_Mew runs gave the correct count. Inside one 36k-file repository,
built-in Glob stays as fast, so the gain is in large or unknown locations and
in date or size filters.

All numbers come from one Windows 11 computer with Everything 1.4.1.1024 and
about 8.8 million indexed files. Your numbers depend on the disk, the tree
size, and the Everything index settings.

### Highlights

- **No SDK DLL.** The new `native-ipc` backend speaks the documented
  Everything IPC protocol directly. It bounds every message with a timeout and
  checks every reply. The SDK DLL and `es.exe` stay available as fallbacks.
- **Memory goes back after each call.** The lite server runs each Everything
  tool call in a short-lived isolated worker. After ten searches, the resident
  server used 18.2 MB instead of 22.8 MB, and a stuck worker is stopped after
  30 s.
- **Fewer agent turns.** `everything_search` returns `totalCount`, loads with
  the Claude Code session, and documents the Everything 1.4 syntax. In our runs
  every Everything_Mew task finished in two turns.
- **Faster scoped queries.** The server lets a leading indexed filter run
  before the scope. A scoped `ext:py` search took 27 ms instead of 64 ms.
- **Clear failures.** Backend, query, policy, and configuration failures set
  `isError=true` with an `error.code`, and the one-shot runner exits with `1`.
- **Allowed-root policy.** This is the first release that enforces
  `EVERYTHING_MCP_ALLOWED_ROOTS` and rejects device-path bypasses.
- **Verified IPC peer.** Native IPC talks only to an Everything window that
  `EVERYTHING_EXE` owns. It opens UIPI only when Everything runs at a lower
  integrity level, and it escapes invisible and bidirectional characters in
  file names before the model sees them.

### Validation

- 549 pytest cases, Ruff, and strict mypy across 38 source and test files
  passed on local Python 3.13.
- An impersonation test registered the Everything window class in a separate
  process that returned a fake path. With the owner check, the call failed
  before the query was sent; without it, the fake path was accepted.
- Native IPC returned the same results as the Everything SDK DLL for six query,
  sort, and metadata combinations on a live index.
- Live ASCII, Korean, and emoji file names passed through native IPC.
- `scripts/measure_lite_sessions.ps1` passed with two lite and two FastMCP
  sessions. All 12 owned processes exited, and the independent PID recheck was
  clean.
- Bandit reported only low-severity notes for fixed-argument `subprocess`
  calls without a shell.

### Upgrade

1. Install the `v0.4.0` tag in a clean virtual environment.
2. Run the allowed-root policy check from the README.
3. Set `EVERYTHING_MCP_ALLOWED_ROOTS` to the directories that agents may
   search.
4. Remove `EVERYTHING_SDK_DLL` unless you want the SDK backend. To keep it,
   also set `EVERYTHING_MCP_BACKEND=sdk`.
5. Restart the MCP host. Confirm that `everything_status` reports
   `native-ipc` and `dbLoaded=true`.

Check scripts that read results. A failed call now has `isError=true`, and
the one-shot runner exits with `1` instead of `0`.

### Known limitations

- Everything_Mew is Windows-only and needs the standard Everything
  application.
- Each lite tool call costs about 75 ms more than in-process execution. Set
  `EVERYTHING_MCP_EXECUTION=inprocess` if latency matters more than returned
  memory.
- `claude -p` spends about 3 s connecting to any MCP server. An interactive
  session pays this once.
- Only native IPC checks the owner of the Everything window. The forced `sdk`
  and `es` backends do not.
- Ordinary words in a file name can still try to instruct the agent. The
  server marks paths as untrusted data, but it cannot remove such words without
  changing the data.

## 한국어

### 요약

0.4는 Everything 인덱스를 Windows 에이전트 작업의 빠른 파일 탐색 경로로
만듭니다. 에이전트는 보통 디렉터리를 순회해 파일을 찾고, 순회는 트리가
클수록 느려집니다. Everything 질의는 트리를 순회하지 않으므로 약 0.1초에
끝납니다.

| 파일 60만 3천 개의 사용자 프로필에서 검색 | Claude Code Glob | PowerShell 순회 | Everything_Mew |
| --- | ---: | ---: | ---: |
| `*.toml` | 9.0초 | 25.7초 | 0.15초 |
| `pyproject.toml` | 10.2초 | 25.8초 | 0.11초 |
| 오늘 수정된 `.py` | 지원 안 함 | 29.3초 | 0.18초 |

`claude -p`(Sonnet, 과제당 2회)로 처음부터 끝까지 실행한 "오늘 수정된 `.py`"
과제는 Everything_Mew를 쓰면 16.5초, 기본 도구만 쓰면 216.7초가 걸렸습니다.
"모든 `pyproject.toml` 찾기" 과제는 27.2초에서 18.8초로 줄었고, Everything_Mew
2회 모두 개수가 정확했습니다. 파일 3만 6천 개의 저장소 하나 안에서는 기본
Glob도 충분히 빠르므로, 이득은 크거나 위치를 모르는 범위와 날짜·크기 조건에서
나옵니다.

모든 수치는 Windows 11 컴퓨터 한 대(Everything 1.4.1.1024, 색인 파일 약
880만 개)에서 측정했습니다. 실제 수치는 디스크, 트리 크기, Everything 색인
설정에 따라 달라집니다.

### 주요 변경 사항

- **SDK DLL이 필요 없습니다.** 새 `native-ipc` 백엔드가 공개된 Everything IPC
  프로토콜을 직접 사용합니다. 모든 메시지에 시간 제한을 두고 모든 응답을
  검사합니다. SDK DLL과 `es.exe`는 대체 경로로 남아 있습니다.
- **호출마다 메모리를 반환합니다.** lite 서버는 Everything 도구 호출마다 수명이
  짧은 격리 워커를 실행합니다. 검색 10회 후 상주 서버 메모리는 22.8MB에서
  18.2MB가 됐고, 멈춘 워커는 30초 뒤 중단됩니다.
- **에이전트 턴이 줄었습니다.** `everything_search`는 `totalCount`를 반환하고,
  Claude Code 세션과 함께 로드되며, Everything 1.4 문법을 설명합니다. 측정에서
  Everything_Mew를 쓴 과제는 모두 2턴에 끝났습니다.
- **범위 검색이 빨라졌습니다.** 색인된 필터로 시작하는 쿼리는 범위보다 먼저
  실행됩니다. 범위를 지정한 `ext:py` 검색이 64ms에서 27ms로 줄었습니다.
- **실패가 분명해졌습니다.** 백엔드·쿼리·정책·설정 실패는 `error.code`와 함께
  `isError=true`를 반환하고, one-shot 실행기는 `1`로 종료합니다.
- **허용 경로 정책을 적용합니다.** `EVERYTHING_MCP_ALLOWED_ROOTS`를 실제로
  적용하고 장치 경로 우회를 거부하는 첫 릴리스입니다.
- **IPC 상대를 확인합니다.** 네이티브 IPC는 `EVERYTHING_EXE`가 소유한
  Everything 창하고만 통신합니다. Everything이 낮은 무결성 수준일 때만 UIPI를
  열고, 모델이 보기 전에 파일 이름의 보이지 않는 문자와 양방향 제어 문자를
  이스케이프합니다.

### 검증

- 로컬 Python 3.13에서 pytest 549건, Ruff, 소스·테스트 38개 파일에 대한
  strict mypy를 통과했습니다.
- 가장 공격 시험에서 별도 프로세스가 Everything 창 클래스를 등록하고 가짜
  경로를 돌려주게 했습니다. 소유자 확인을 켜면 쿼리를 보내기 전에 호출이
  실패했고, 끄면 가짜 경로가 결과로 들어왔습니다.
- 실제 인덱스에서 쿼리·정렬·메타데이터 조합 6가지에 대해 네이티브 IPC 결과가
  Everything SDK DLL과 같았습니다.
- 네이티브 IPC로 ASCII, 한글, 이모지 파일 이름을 실제로 검색했습니다.
- `scripts/measure_lite_sessions.ps1`을 lite 세션 2개와 FastMCP 세션 2개로
  통과했습니다. 소유한 프로세스 12개가 모두 종료됐고 독립 PID 재검사도
  깨끗했습니다.
- Bandit은 셸 없이 고정 인수로 호출하는 `subprocess`에 대한 낮은 심각도 알림만
  보고했습니다.

### 업그레이드

1. 깨끗한 가상 환경에 `v0.4.0` 태그를 설치하세요.
2. README의 허용 경로 정책 확인 명령을 실행하세요.
3. 에이전트가 검색할 디렉터리를 `EVERYTHING_MCP_ALLOWED_ROOTS`로 지정하세요.
4. SDK 백엔드를 쓰지 않으면 `EVERYTHING_SDK_DLL`을 지우세요. 계속 쓰려면
   `EVERYTHING_MCP_BACKEND=sdk`도 설정하세요.
5. MCP 호스트를 재시작하고 `everything_status`가 `native-ipc`와
   `dbLoaded=true`를 보고하는지 확인하세요.

결과를 읽는 스크립트를 점검하세요. 실패한 호출은 이제 `isError=true`이고,
one-shot 실행기는 `0` 대신 `1`로 종료합니다.

### 알려진 제한 사항

- Everything_Mew는 Windows 전용이며 표준 Everything 애플리케이션이 필요합니다.
- lite 도구 호출은 인프로세스 실행보다 약 75ms 더 걸립니다. 메모리 반환보다
  지연이 중요하면 `EVERYTHING_MCP_EXECUTION=inprocess`를 설정하세요.
- `claude -p`는 MCP 서버에 연결하는 데 약 3초를 더 씁니다. 대화형 세션은 이
  비용을 한 번만 냅니다.
- Everything 창의 소유자는 네이티브 IPC만 확인합니다. 강제 지정한 `sdk`와
  `es` 백엔드는 확인하지 않습니다.
- 파일 이름 속 일반 단어로 에이전트에게 지시하려는 시도는 여전히 가능합니다.
  서버는 경로를 신뢰할 수 없는 데이터로 표시하지만, 데이터를 바꾸지 않고 그런
  단어를 없앨 수는 없습니다.
