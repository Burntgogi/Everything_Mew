# Everything_Mew v0.2.0 Release Notes / 릴리스 노트

Status: final release dated 2026-07-17. The Python package version is `0.2.0`
and the Git tag is `v0.2.0`. This release promotes the reviewed
`v0.2.0-rc.1` candidate without changing its public tool contracts.

상태: 2026-07-17 최종 릴리스입니다. Python 패키지 버전은 `0.2.0`, Git
태그는 `v0.2.0`입니다. 공개 도구 계약을 바꾸지 않고 검토된
`v0.2.0-rc.1` 후보를 승격했습니다.

## English

### Summary

Version 0.2 replaces the always-heavy default deployment with a direct,
dependency-light stdio MCP runtime for Codex Desktop and other hosts that keep
one process alive per active session. The lite runtime does not require FastAPI
or FastMCP and loads the Everything backend only when a tool is called. The
FastMCP path remains available as an optional compatibility mode.

### Highlights

- Add `everything-mew-lite`, `everything-mcp-lite`, and
  `python -m everything_mcp.lite_stdio` entrypoints.
- Handle MCP initialization, notifications, request IDs, schemas, and tool
  errors at the MCP 2025-11-25 boundary without importing FastMCP while idle.
- Use the official asynchronous Everything SDK reply-window flow with a
  15-second deadline and process-wide serialization.
- Make `everything_count` total-only with zero request flags and
  `Everything_SetMax(0)`.
- Compose `C:\Work\project` as the exact recursive scope
  `"C:\Work\project\"` and discard results outside that boundary.
- Parse grouping, quoting, negation, and every OR branch before broad-query
  checks. Regex branches need a separate indexed narrowing filter.
- Treat Everything 1.4.1 as the default syntax profile. Known Everything 1.5
  `content*:`, ADS aliases, nested content modifiers, and `from-disk:` require
  a non-root scope plus a separate indexed filter in every affected branch.
- Keep SDK reply IDs unique across adapter instances, reject stale replies
  after Windows handle reuse, and preserve failed callback cleanup for retry.
- Decode ES metadata CSV as UTF-8 and retrieve SDK paths through the documented
  required-length API.
- Normalize repository text to LF so clean Windows checkouts produce
  byte-stable wheel and sdist inputs regardless of `core.autocrlf`.
- Support Windows CPython 3.11 through 3.14.

### Validation

- 407 pytest cases, Ruff, and strict mypy passed on local Python 3.11.
- Windows GitHub Actions passed on Python 3.11 and 3.14 for the reviewed
  candidate commit and tag.
- An isolated installed wheel completed the lite MCP lifecycle without
  `PYTHONPATH`, FastAPI, or FastMCP.
- The final live query `size:>100mb` returned 1,005 unique SDK results from
  Everything 1.4.1.1032. Every result exceeded 100 MiB and was size-sorted;
  the public first 100 entries exactly matched the independent SDK oracle.
- Source and distribution archives were checked for credentials, `.env` files,
  SDK binaries, caches, `_nonrelease/`, and machine-specific path evidence.
  The path-bearing report remains local and is not a release asset.

### Upgrade

```powershell
py -m pip install --upgrade .
```

Install the optional FastMCP compatibility path only when required:

```powershell
py -m pip install --upgrade ".[server]"
```

Use `everything-mew-lite` for Codex Desktop and other always-enabled local MCP
hosts. Existing `everything-mew` and `everything-mcp` configurations remain
available when the `[server]` extra is installed.

### Known limitations

- Everything_Mew is Windows-only and requires a running standard Everything
  installation. Everything Lite does not expose the required IPC interface.
- The SDK backend requires a trusted architecture-matching Everything SDK DLL.
- Hosts can still create one process per active session. Version 0.2 lowers
  per-process standby cost; host session cleanup controls the process count.
- HTTP is neither required nor enabled automatically.

## 한국어

### 요약

0.2는 활성 세션마다 프로세스를 하나씩 유지하는 Codex Desktop 등의 호스트를
위해 상시 대기 부담이 큰 기본 배포 대신 직접 구현한 의존성 경량 stdio MCP
런타임을 제공합니다. lite 런타임은 FastAPI나 FastMCP를 요구하지 않고 도구가
호출될 때만 Everything 백엔드를 로드합니다. FastMCP 경로는 선택 가능한 호환
모드로 유지합니다.

### 주요 변경 사항

- `everything-mew-lite`, `everything-mcp-lite`,
  `python -m everything_mcp.lite_stdio` 진입점을 추가했습니다.
- 대기 중 FastMCP를 import하지 않고 MCP 2025-11-25 경계에 맞춰 초기화,
  notification, 요청 ID, 스키마, 도구 오류를 처리합니다.
- 공식 비동기 Everything SDK 응답 창 흐름, 15초 제한, 프로세스 전체
  직렬화를 사용합니다.
- request flag 0과 `Everything_SetMax(0)`으로 `everything_count`를 실제
  total-only 호출로 만들었습니다.
- `C:\Work\project`를 정확한 재귀 scope `"C:\Work\project\"`로 합성하고
  경계 밖 결과를 제거합니다.
- 그룹, 인용, 부정, 모든 OR 분기를 광범위 쿼리 검사 전에 파싱하며 정규식
  분기에는 별도 인덱스 축소 필터를 요구합니다.
- Everything 1.4.1을 기본 문법 프로필로 사용합니다. 알려진 Everything 1.5
  `content*:`, ADS 별칭, 중첩 content modifier, `from-disk:`는 관련된 모든
  분기에서 루트가 아닌 scope와 별도 인덱스 필터를 요구합니다.
- 어댑터 간 SDK 응답 ID를 고유하게 유지하고 Windows 핸들 재사용 뒤의 오래된
  응답을 거부하며 콜백 정리 실패 객체를 재시도까지 보존합니다.
- ES 메타데이터 CSV를 UTF-8로 디코딩하고 문서화된 필요 길이 API로 SDK
  경로를 가져옵니다.
- 저장소 텍스트를 LF로 고정해 `core.autocrlf`와 관계없이 깨끗한 Windows
  체크아웃의 wheel·sdist 입력 바이트를 안정화했습니다.
- Windows CPython 3.11부터 3.14까지 지원합니다.

### 검증

- 로컬 Python 3.11에서 pytest 407건, Ruff, strict mypy를 통과했습니다.
- 검토된 후보 커밋과 태그의 Windows GitHub Actions가 Python 3.11과 3.14에서
  통과했습니다.
- 격리 설치한 wheel이 `PYTHONPATH`, FastAPI, FastMCP 없이 lite MCP 수명
  주기를 완료했습니다.
- 최종 `size:>100mb` 실환경 검색에서 Everything 1.4.1.1032 SDK 결과
  1,005건이 모두 고유하고 100 MiB를 초과하며 크기순임을 확인했습니다. 공개
  첫 100건은 독립 SDK 원본과 정확히 일치했습니다.
- 소스와 배포 아카이브에서 자격 증명, `.env`, SDK 바이너리, 캐시,
  `_nonrelease/`, 컴퓨터별 경로 증거가 없는지 검사했습니다. 경로 포함 보고서는
  로컬에만 보관하며 릴리스 자산으로 게시하지 않습니다.

### 업그레이드

```powershell
py -m pip install --upgrade .
```

FastMCP 호환 경로가 필요한 경우에만 선택 사항을 설치합니다.

```powershell
py -m pip install --upgrade ".[server]"
```

Codex Desktop과 항상 켜 두는 로컬 MCP 호스트에는 `everything-mew-lite`를
사용하세요. `[server]` 선택 사항을 설치하면 기존 `everything-mew`와
`everything-mcp` 설정도 계속 사용할 수 있습니다.

### 알려진 제한 사항

- Everything_Mew는 Windows 전용이며 표준 Everything이 실행 중이어야 합니다.
  Everything Lite는 필요한 IPC 인터페이스를 제공하지 않습니다.
- SDK 백엔드에는 Python 비트수와 맞는 신뢰할 수 있는 Everything SDK DLL이
  필요합니다.
- 호스트는 활성 세션마다 프로세스를 하나씩 만들 수 있습니다. 0.2는 프로세스별
  대기 비용을 줄이며 프로세스 수 정리는 호스트의 세션 수명 주기가 담당합니다.
- HTTP는 필요하지 않으며 자동으로 활성화하지 않습니다.
